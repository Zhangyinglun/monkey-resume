# MonkeyResume 模型主导重设计：实施方案

状态：方案已获授权并完成仓库实现；实际检查与限制见
[`../validation/model-first-workflow.md`](../validation/model-first-workflow.md)。
以下保留规划阶段的决策与实施顺序；个人工作区未迁移。

## 已确定的流程

新增独立入口：简历或信息文档 → 完整来源保存 → 模型结构化 → 增量入库。
它不需要 JD，也不受一页限制；之后再进入定制简历流程。

原始 JD 核心需求 → 完整缓存核对 → 重写工作经历和 summary → 按 JD
构造技能栏 → 统一内容与格式审查 → 一页交付。

模型负责语义和编辑判断。程序保存事实与历史、验证可确定的引用/版本
问题并生成文档。唯一模型维护草稿含 `target / resume / evidence_links /
omissions`；计算元数据和机器记录由程序生成。

数据契约的完整决定保存在
[事实、候选人身份与简历展示应该如何解耦？](https://github.com/Zhangyinglun/monkey-resume/issues/7)。

## 实施顺序

### 1. 先锁定新契约和失败保护

添加合成回归样例和新契约测试。测试身份更正、项目归属、多来源引用、
失效证据、无来源字段、过期上下文和审查绑定。未知契约版本拒绝。
同时覆盖中文信息笔记、不完整文档、重复导入、精简简历的增量合并、
来源定位、冲突保留和缓存事务失败；抽取到文字不等于成功入库。
不要将简单字符串或数字集合测试包装成语义准确性测试。

契约编译器使用纯计算接口，测试与实际 CLI 共用该接口。新的测试应覆盖
真实调用链，而不是给生产函数复制一个替代实现。旧接口测试按新契约
替换，不为保留旧测试绿灯重新增加兼容代码。

完成条件：有明确可复现的错误样例；已证实新实现前该路径不具备预期行为。

### 2. 实现独立缓存写入、稳定上下文与草稿编译

调整 `scripts/evidence_ledger_manager.py`、`scripts/resume_shared.py` 和
新草稿模块，提供完整有效上下文与直接编译入口。固定候选人/实体身份，
显示更正通过证据选择生效；项目归属有明确来源，事实不搬到展示章节。
新增确认事实可以没有 Snapshot 路径，但必须先入账而非由草稿创造。

扩展 `scripts/extract_resume_text.py` 或新来源抽取模块，保存文档结构与定位；
用模型理解简历/信息笔记，替代固定英文标题/分隔符的事实正则解析。
单独支持首次建库和后续增量写入，无需 JD。原件、解析快照和来源记录
不可变；短文档遗漏不撤销已有经历，重复文件不重复入账，更正与冲突明确
处理。来源登记、Ledger、Profile 通过暂存/事务一并提交，失败保留旧缓存。

程序生成纯展示 resume、当前契约的 manifest、机械变更记录和已知问题。
移除对 plan/language、单实体 summary 和固定段落数量的运行依赖。
支持用户否认的能力作为事实：技术词出现在来源里不代表正向使用经验，
否认不得因技术词提取而变成技能支持。

完成条件：姓名、教育、任职项目展示及跨任职 summary/skills 通过新契约
测试；无效、撤销、错误归属或失效上下文不能编译成可发布结果。
简历和信息文档能独立、可追溯地入库，未知字段不变成占位符事实，增量
合并与失败保护通过，输出实际写入路径及新增/更正/待澄清报告。

### 3. 分离候选生成与 Accepted 发布

调整 `scripts/generate_final_resume.py` 及审计/报告连接层，形成候选准备和
审查后发布两个明确动作。准备阶段不覆盖 Accepted Resume，也不创建
“已接受”的历史记录；返回草稿、同源 DOCX/PDF 和页面测量给宿主审阅。

宿主模型执行统一审查后，程序核对报告与草稿/证据/渲染绑定再发布。
词数、动词字典和技能组数等浅层警告改为提示，不需要模型逐项写免责
disposition 才能生成正确简历。保留真正来源/版本错误和实际页面失败。

target 的公司/岗位/链接贯穿记录；未知值不编造。DOCX/PDF 模板和历史
事务优先复用，不借重设计替换成熟渲染实现。

完成条件：缺少审阅、过期审阅、两页、裁切或未完成视觉检查不发布；
失败时旧 Accepted Resume、历史索引和已接受文件保持不变。

### 4. 替换 Skill 和过时规则

将 `SKILL.md` 组织为用户确认的五步；替换相关 references、README、领域
契约和受影响 ADR。按分支披露参考资料，让模型不用每次读所有协议。
增加“只导入或更新资料缓存”的独立触发分支，不强迫该分支要求 JD 或
生成定制简历。
只暴露实际已实现的命令，不先写一个不存在的 CLI。

删除旧 plan/language 和旧 manifest 接口的指令及无用运行代码，不做
兼容适配。删除前检查依赖和既有其他调用方，超出本仓库的更新另行授权。
保留候选事实、来源和历史文件；实际个人工作区不自动迁移。

完成条件：常规执行只维护一份草稿；所有文档与真实入口一致，没有旧规则
暗中重新限制模型；宿主更高优先级指令仍受到尊重。

### 5. 对照验证后才切默认入口

用固定原始 JD、事实和澄清答案比较基线与新流程，保留未用于提示调优的
案例。生成质量、审阅漏报/误报、实际一页和视觉可读性分别报告。
发生分歧时查看来源和具体理由，不靠总体分数或多数票抵消事实问题。

现有小试只验证两个裁判上下文在四份文本上的表现，不是端到端验证。
后续需要真实同源文档、完整流程测试及必要的人工校准。用户资料用于
真实测试或迁移时，先明确授权和输出位置，不上传到公共 issue。

完成条件：新路径的关键回归场景无未解决失败，实际同源输出通过一页及
视觉检查，结果和限制可追溯。检查包括仓库 lint、unittest 和 Skill 校验，
但全套测试通过也不是招聘效果或普遍语义正确性的证明。

## 单页编辑与停止策略

使用现有已批准的 DOCX 默认版面作为起点：A4、正文约 10.5 pt、上下边距
12.7 mm（来源：`references/docx-output.md`）。这是布局起点，不是选材算法。
先精简重复、合并次要信息，再小幅调整布局；自动排版不删除正文。

保留对岗位最有意义的职责、机制、规模和成果。末尾留白不自动触发新增
无价值内容。工作内部相关贡献在前，不强制每个雇主占相同空间、不要求
每条 bullet 都有百分比。候选人的明确必须展示要求优先进入取舍判断。

只有有具体可修的问题或新证据时继续返修。重复同一争议而没有新事实/
新修改，或者一页与候选人明确的必留内容冲突时，提交具体候选取舍给用户。
独立审阅或渲染不可用时保存未验证草稿、如实说明缺口，不冒充已通过。

## 旧数据的一次性迁移

这是后续独立、显式执行的操作，不是新流程的旧接口兼容。先备份并验证
输入，保留 IDs、原始来源、确认、更正和撤销历史；无法证明的关系保持
缺失，不能猜测填充。验证新数据后才提交转换，失败恢复备份。
Accepted Resume 和历史文档不清理。本方案没有对个人工作区执行任何操作。

## 实施授权边界

原规划交付不包含正式代码实施。用户随后明确授权“开始”，仓库代码、
Skill、CLI、文档和回归测试现已实施。授权未扩大到推送代码、更新其他
仓库调用方或迁移个人资料；这些操作仍需单独授权。
