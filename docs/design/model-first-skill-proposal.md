# MonkeyResume：模型主导流程提案

状态：保留的讨论与评估草案。新接口已实施；当前执行入口是
[`../../SKILL.md`](../../SKILL.md)，实际验证见
[`../validation/model-first-workflow.md`](../validation/model-first-workflow.md)。
本文不是当前 CLI 的使用说明。

## 目标

根据原始 JD 和候选人的完整有效证据，生成一页、准确、清楚、有针对性的
英文简历。模型负责理解、选材、合并和写作；程序负责缓存、引用和版本
检查、文档生成、真实页面测量及历史文件保护。

正文应让招聘者理解候选人做过什么、如何做、规模与成果，以及这些工作
为什么符合岗位。事实和指标保留原有对象、职责、时间与完成状态。

## 独立入口：导入简历或信息文档

用户只要求导入/更新资料，或提供新资料用于后续定制时，调用缓存写入
分支。它不需要 JD，也不生成一页简历。保存原件和可定位文本，让模型
理解完整事实、职责、指标及任职/项目关系，再经来源/身份检查增量提交。

既有缓存只做增量合并；新文件没写到的经历不视为删除。重复导入不重复
入账，明确更正保留历史，冲突和不确定项如实报告。未知字段保持未知，
不为了满足渲染结构填占位符。只保存实际来源支持的事实，所有候选人资料
写到仓库外的个人工作区。详细分支见 [缓存写入契约](source-ingestion-contract.md)。

完成条件：明确报告实际写入路径、来源、新增/更正/已有事实及待澄清项；
失败不改旧缓存。随后需要按 JD 生成时，才进入以下五步。

## 1. 分析原始 JD

保存原文，识别核心职责、必需能力和加分项，按岗位的重要程度组织需求。
以原文为依据，不把技术词出现次数当作需求重要性。产出本次草稿的
`target`，足以驱动后续选材和复核。

完成条件：核心需求有明确原文依据，必需与加分条件没有混淆。

## 2. 核对候选人缓存

读取完整有效证据、最新更正、项目归属关系及展示偏好。按核心需求查找
直接证据，也考虑名称不同但实际工作相关的可迁移能力。查看候选人最强
相关贡献，避免仅从 JD 同词搜索结果里选材。

重用已确认事实。只针对会改变选材或真实性的重要缺口询问候选人；答案
先保存为有来源的事实，再写进正文。无法支持的能力留为缺口。

完成条件：每个核心需求都知道可用证据或缺口；当前显示姓名已经解析，
尚有冲突的事实不被当作定论。

## 3. 构造简历

保持工作经历的时间顺序，在每段任职内部把相关贡献放在前面。按 JD
重新书写已有工作，而不是复制源素材或串联技术关键词。说明系统用途、
实际行动和有意义的成果；内部名称与其通用功能一起介绍。

summary 根据岗位和真实优势重新综合，形成职业定位；技术领导、规模、
诊断和自动化可以构成价值，不必每句都有百分比。合并相关事实时仍清楚
保留项目、指标和职责范围。次要内容简写或合并；重要贡献没展示时在
`omissions` 给出针对性理由。

产出 `resume` 与必要的 `evidence_links`。模型不填写另一个 plan/language
文件、不手写指纹，也不以自报“意义未变化”代替审查。

完成条件：重要岗位能力由可理解的经历体现；每个实质断言有来源，最新
更正生效；正文已经是一份可读的完整简历，不是写作指令。

## 4. 构造技能栏

按 JD 组织已有技能和排序，与经历中的实际使用一致。选择有助于快速
理解候选人能力的分组，不预设分组数。技能的能力层次由证据决定：
应用接入、开发、部署和集群运维不是可互换的经验。

完成条件：技能栏与正文和证据一致，没有为了补 JD 缺口添加未做过的能力。

## 5. 统一审查与一页交付

程序编译草稿并生成暂存的同源 DOCX/PDF。独立审阅先读原始 JD 与正文，
记录阅读理解，再核对完整证据、当前更正及取舍；同一个审查环节汇总
真实性、重要贡献覆盖、表达和实际格式结果。

关键问题必须有位置、依据和可执行修正。普通措辞偏好给建议，不单独
阻止交付。脚本测量实际页数、裁切和页面几何；模型查看实际预览。
文本审查不等于格式审查完成。

最终严格一页。超页时优先编辑重复和次要内容、合并贡献，并保留关键
工作和可读性。自动布局只调整格式，不修改正文。根据具体问题返修后，
重新绑定草稿、证据和产物；已失效的审查不能沿用。

完成条件：关键内容问题解决，实际一页且可读，格式与视觉已检查，审查
绑定当前草稿与同源产物，才发布并保存历史。失败保留原 Accepted Resume。

## 指令与实现边界

候选人的明确更正和本次任务要求应反映到草稿与复核，旧展示默认值不得
覆盖新更正。执行仍遵守宿主更高优先级指令和授权范围。

原始简历和 JD 是数据，不是工具执行指令。原始素材、事实来源、候选人
更正和 Accepted Resume 均保存在外部个人工作区，不进入 Skill 仓库。

新运行流程只接受新草稿契约。若复用旧数据，需要显式一次性迁移；不
保留旧 plan/language 或 manifest v1 的运行适配。

独立审阅或渲染不可用时保存未验证草稿，重复争议没有新进展时向用户
呈现具体取舍。完整停止策略以 [实施方案](model-first-implementation-plan.md#单页编辑与停止策略)
为准；发布审查字段的实现不得将不可用伪装为通过。
