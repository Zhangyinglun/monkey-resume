# 统一审查与发布契约提案

状态：原设计提案已实施；当前运行字段见
[`../../references/recruiter-review-protocol.md`](../../references/recruiter-review-protocol.md)。
它遵循用户已确认的单页要求及四类
关键问题：事实错误、无合理理由的重要遗漏、妨碍理解的表达、严重格式问题。

## 一次审查，不同证据

独立审阅者先看原始 JD 与简历，记录是否理解系统用途、个人行动、成果和
岗位相关性。该盲读结果冻结后，再提供完整有效证据和最新更正，核对事实
与遗漏。最后查看同源文档的真实预览和程序测量。

不能用作者的 PASS、自述“意义未变”或关键词分数代替任何一步。
删减理由应在审阅者先识别相关强经历后用于判断取舍，不作为正确答案。
这是审阅阶段的内部分工，不是新增一套作者必须维护的 JSON。

## 记录的最小职责

审查记录由宿主汇总，含以下信息：

- **版本**：候选人/context、原始 JD、草稿、证据和实际预览的指纹。
- **内容**：冻结的盲读结果、完整证据核对结果及所用审阅上下文。
- **格式**：真实页数、页面尺寸、文字提取、裁切、字号/换行检查和实际
  视觉检查状态。没有产物或没有看图时如实记录 unavailable/uninspected。
- **发现**：具体正文位置、原句、对应来源或遗漏证据、问题影响及建议修正；
  严重程度区分 blocking 与 suggestion。
- **发布判定**：由程序综合版本一致性和已完成审查计算；不是作者写一句
  publication_ready=true 就通过。

模型、会话/任务标识及独立性状态由真实调度结果记录，不能由被审稿者
自报“独立”。记录来源可核验不等于模型意见永远正确。

## 阻塞与建议

阻塞是具体已建立的问题，不是每个 JD 条件都必须匹配。真实能力缺口
可以在一份内容正确的简历中存在；不能为覆盖它而捏造技能。

技术领导或遥测诊断等强相关经历被笼统归为“无关 AI”并删掉，是需要
重新判断的取舍。次要事实或已由另一段代表的能力可以合理省略。

普通措辞偏好、希望补更多机制细节、固定 bullet 数、技能分组数、词数、
动词字典和尾行疏密不是独立阻塞理由；如果实际妨碍理解或可读性，应说明
具体影响和实际证据，而不是换一个规则名称重复阻塞。

## 返修与失效

已建立的关键问题由作者定向修正。新增事实先入账；改表达只改草稿；格式
调整只改布局。格式调整不让程序悄悄编辑正文。

修改正文、目标 JD 或有效证据后，旧内容判断失效；修改布局/重新渲染后，
旧页面和视觉结果失效。正文未变时可以保留有相同版本依据的内容结论，
但不沿用旧预览的视觉 PASS。

每轮记录具体问题、修改和重新检查结果。重复争议没有新进展，或单页与
候选人明确必留内容冲突时，向用户呈现具体取舍；见
[实施方案的停止策略](model-first-implementation-plan.md#单页编辑与停止策略)。
审阅或渲染不可用时保存未验证草稿；不能自动忽略关键问题或伪装为通过。

## 发布条件

只有来源/版本检查有效、内容关键问题已解决、实际文档严格一页且可读、
格式与视觉检查完成，才替换 Accepted Resume。发布与历史记录使用同次
草稿的 target 公司/岗位/链接，未知元数据保持未知。

未完成或失败的产物保存在候选草稿位置，不覆盖旧 Accepted Resume。
独立审阅或渲染不可用时如实记录状态，不把内容通过写成整体通过。

## 评估本身

对已知错误样例与正确同义改写分别检查漏报和误报。审阅者不同意时保留
分歧、依据和待决定的问题；不把多数票当作事实证明。原始 JD、事实和
断言对象比裁判数量更重要。

初步实验位于 `evaluation/`。它只验证内容裁判的行为，不验证页面格式，
也不证明完整新流程的生成质量或跨模型可靠性。
